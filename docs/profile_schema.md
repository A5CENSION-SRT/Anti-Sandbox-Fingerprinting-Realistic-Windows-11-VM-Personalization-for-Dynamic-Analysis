# ARC — PersonaContext Profile Schema

The canonical persona schema is defined in `core/persona_context.py` as a frozen Pydantic
`BaseModel` with `extra="forbid"`. Every field listed here is validated at load time; unknown
keys raise `ValidationError`. This schema is consumed directly by all 33+ artifact services via
`ServiceContext.persona` — no filtering, no bridging (ADR-001).

---

## Core Identity Fields

| Field | Type | Constraints | Description |
|---|---|---|---|
| `full_name` | `str` | required | Display name used in document metadata and shell artefacts |
| `username` | `str` | `^[a-z][a-z0-9_.]{2,19}$` | Windows logon name; must match `C:\Users\<username>` in image |
| `email` | `str` | required | Primary email address; appears in Outlook/browser autocomplete |
| `organization` | `str` | required | Employer or "Self"; used in Office document properties |
| `occupation` | `str` | required | Job title; drives AI prompt context and work-style defaults |
| `department` | `str \| None` | optional | Org unit; null for freelancers |

---

## Demographic Fields

| Field | Type | Constraints | Description |
|---|---|---|---|
| `age_range` | `str` | `^\d{2}-\d{2}$` | e.g. `"29-33"`; used in persona coherence checks |
| `locale` | `str` | default `"en_US"` | BCP-47 locale; drives timestamp TZ conversion and holiday calendar |
| `location` | `str \| None` | optional | City/state hint; appears in browser geolocation seeds |

## Behavioral Fields

| Field | Type | Constraints | Description |
|---|---|---|---|
| `tech_proficiency` | `TechProficiency` | `low\|intermediate\|high` | Controls app set complexity and CLI-vs-GUI artifact ratio |
| `interests` | `PersonaInterests` | see below | Nested model: hobbies, professional topics, entertainment |
| `work_style` | `PersonaWorkStyle` | see below | Nested model: description, typical_tools, collaboration style |

### PersonaInterests

| Field | Type | Constraints |
|---|---|---|
| `hobbies` | `list[str]` | 3–10 items |
| `professional_topics` | `list[str]` | 2–8 items |
| `entertainment` | `list[str]` | default empty |

### PersonaWorkStyle

| Field | Type | Default |
|---|---|---|
| `description` | `str` | required |
| `typical_tools` | `list[str]` | required |
| `collaboration_style` | `str` | `"hybrid"` |
| `meeting_frequency` | `str` | `"moderate"` |

| `colleague_names` | `list[str]` | 5–20 items | Appear in email-stub content and recent-contacts registry keys |

## Work Pattern / Schedule Fields

| Field | Type | Default | Constraints | Description |
|---|---|---|---|---|
| `work_hours_start` | `int` | `9` | 0–23 | Hour (UTC) when daily session begins |
| `work_hours_end` | `int` | `17` | 0–23 | Hour (UTC) when daily session ends |
| `active_days` | `list[int]` | `[1,2,3,4,5]` | ISO weekdays (1=Mon) | Days on which EventScheduler emits activity |

## Artifact Generation Context Fields

| Field | Type | Default | Constraints | Description |
|---|---|---|---|---|
| `profile_archetype` | `Literal` | `"home_user"` | `developer\|office_user\|home_user` | Controls expansion content theming and app-set defaults |
| `installed_apps` | `list[str]` | `[]` | — | Executable names written to Prefetch and UserAssist |
| `browsing_categories` | `list[str]` | `["general"]` | — | URL category pool for EventScheduler URL_VISIT payloads |
| `daily_avg_sites` | `int` | `50` | 1–500 | Informs scheduler Poisson lambda for URL_VISIT events |
| `timeline_days` | `int` | `360` | 1–3650 | Length of simulated activity window in days (ADR-004) |
| `windows_build_hint` | `Literal` | `"23H2"` | `22H2\|23H2\|24H2` | Affects Prefetch format version and EVTX template selection |
| `hostname_hints` | `list[str]` | `[]` | — | Candidate hostnames; `IdentityGenerator` picks one |

## Seed Container Types

These nested models live in `core/persona_context.py` and are populated by the EXPANSION phase
seed generators (`services/ai/seed_generators/`). They are attached to `ExpansionBundle`, not
directly to `PersonaContext`.

### RegistrySeed

Generated by `RegistrySeedGenerator`. Contains:
- `userassist_apps`: list of ROT13-encoded paths for UserAssist counter injection
- `run_mru_commands`: RunMRU strings (recent Run-dialog entries)
- `typed_paths`: TypedPaths IE/Explorer strings

### EvtxSeed

Generated by `EvtxSeedGenerator`. Contains:
- `application_events`: list of application-specific EVTX event stubs (EID, provider, message)
- `system_events`: system-channel event stubs

### PrefetchAppSeed

Generated by `PrefetchSeedGenerator`. Contains:
- `entries`: list of `(exe_name, run_count_hint)` tuples driving `.pf` file content and
  scheduler APP_LAUNCH frequency weighting

## Loading a Persona

```bash
# Preset (no API key required)
python main.py --vhdx run.vhdx --preset developer --random-seed 4242

# AI-generated (requires GEMINI_API_KEY)
python main.py --vhdx run.vhdx --ai-generate --occupation "Data Scientist" \
    --interests "machine learning,cycling,cooking" --timeline-days 360

# Custom YAML (must validate as PersonaContext)
python main.py --vhdx run.vhdx --persona-yaml ./my_persona.yaml
```

`PersonaLoader` validates the YAML at load time. Extra fields fail loudly. Missing required
fields fail loudly. Partial YAML with only some fields is not supported — use a preset as a
base and override via `--preset` + flags, or write a complete YAML.
